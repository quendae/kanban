# Kanban Slice 3 — Assembly + Testing & Innovation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Original-2014 Assembly Line and Testing & Innovation as deterministic, content-driven systems: assembly parts and car chains, Test Track and Demand, claiming cars/garages, design upgrades, and Tested Design derivation.

**Architecture:** Extend the existing physical-entity model instead of adding counters that duplicate ownership. Cars, Parts, and Designs continue to move through opaque IDs and `EntityLocation`; graph geometry, Demand data, garage benefits, Upgrade-Space benefits, and player-count Test Track configuration are content/ruleset data. Every interaction remains `Command -> Validate -> GameEvents -> Reducer -> Invariants`; the UI only renders legal commands and previews generated by the rules layer.

**Tech Stack:** TypeScript 6, Vitest, React, Vite, pnpm workspace, GitHub Actions CI.

**Spec:** `docs/superpowers/specs/2026-09-07-kanban-digital-adaptation-design.md`

## Global Constraints

- Ruleset is `KANBAN_AR_2014`; do not silently import Kanban EV behavior.
- No `Math.random()` in runtime rules code; all deck/order randomness remains seeded and replayable.
- Total work remains capped at 4 Shifts/day.
- Every physical Car/Part/Design ID has exactly one location.
- Do not infer rules from UI coordinates.
- Do not hard-code unverified printed Demand, garage, Upgrade-Space, or conveyor-board data as authoritative Original content.
- Synthetic fixtures are explicitly `authoritative: false` and replaceable.
- Original 2014 allows replacing a car only when all available garages are occupied; the replacement grants no garage benefit.
- Claim cost is determined from every car's Test Track position before the first car is claimed in that command.
- Test Track capacity is 4 cars in addition to the Pace Car; a fifth entering car removes the car directly behind the Pace Car and compacts the remaining cars.
- Upgrade Design costs 1 Shift, one matching Selected Design, and one matching Part; the normal upgrade increases the global Part value by one (maximum 6), flips the Design to upgraded, and awards 2 PP.
- Tested Design is derived: an owned upgraded Design is tested when the player has at least one garage car of the same Model.
- Meeting scheduling caused by Pace Car crossing a checkered threshold is represented in state/events now but full Meeting resolution remains Slice 5.
- UI motion must explain car push/claim cause-and-effect and obey `prefers-reduced-motion`.

### Task 5: Claim Cars, cost snapshot, Pace Car, garage placement, Original replacement

**Files:**
- Create: `packages/rules/src/testing.ts`
- Modify: commands/errors/events/engine/reducer
- Test: `packages/rules/test/testing-claim.test.ts`

**Interfaces:**
- Command `CLAIM_CARS` contains all claimed car IDs plus one Selected Design ID per car and destination garage decisions.
- `getClaimCostSnapshot(state)` maps current Test Track Car IDs to costs before any car moves: position 1 => 1, positions 2–3 => 2, position 4 => 3.
- Claim total is the sum of those snapshot costs.
- Each claimed car needs one matching-model Selected Design; Designs move to bottom of Central deck.
- Pace Car advances by number claimed; unclaimed Test Track cars compact.
- Empty garage placement grants its content-defined benefit.
- Replacement is legal only when every currently available garage is occupied, returns the replaced car to supply, and grants no benefit.
